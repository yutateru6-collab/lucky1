# lucky 2.0 — 小さな迷いを、あそびに。

2026-09-13の追加要望を実装。従来の理念（50/50、結果は強制しない、入力と記録は任意）を維持。

## 画面と流れ
「あそぶ / カレンダー / ことば」の3画面。モバイルは下部ナビ、PCは左ナビ。暖色のライトと、コントラストを調整したダークテーマ。

1. 何をしようか迷っているかを最大240字でメモ（任意）。
2. 抽選前の気持ちを5種類から選択。別途500字まで文章で書ける（任意）。
3. コイン、じゃんけん、カード、サイコロから選んで抽選。
4. 抽選結果とは独立して「やってみる / 見送る / まだ決めない」を選ぶ。
5. 結果を見た気持ちとひとことを任意で追加し、「カレンダーに残す」で保存。
6. カレンダーの日付から当時のメモ・抽選前後の気持ち・自分の選択を読む。後日の追記・個別削除が可能。

## 抽選の対応
- コイン：各50%。
- じゃんけん：相手の手を3通りから一様抽選。勝ち→やる、負け→やらない。あいこは再選択。決着時は各50%。
- カード：2枚にやるとやらないを公平に割り当て、タップした位置で決定。
- サイコロ：1〜6を一様抽選。奇数→やる、偶数→やらない。

一様整数はWeb Cryptoと棄却法。演出のための引き直しや履歴での確率調整はしない。あいこを「やらない」と扱わない。

## 記録
`lucky.records.v2` を使用。初版の `lucky.records.v1` が同じオリジンにあれば読み替え、保存時に移行する。旧キーは上書きしない。カレンダーは抽選した瞬間の端末のローカル日付を保存する。旧データのローカル日付だけは、元データに情報がないため読み込み端末のタイムゾーンで復元する。

本人の選択は実行完了の証明ではない。「何回行動できた」などと断定しない。上限1,000件で停止し、自動的に古い記録を削除しない。読み込み不正・保存容量不足では上書きを止め、画面上に説明する。

JSONバックアップ書き出し・読み込み。重複IDは既存を優先し、新しいものだけを追加。お気に入りとテーマはバックアップ対象外。端末・ブラウザ・オリジンをまたぐ同期はない。個人メモの外部送信やGoogleカレンダー連携は追加していない。

## ことば
16件のオリジナル文と3件のことわざ。毎日の1件、カテゴリ別、お気に入り。オリジナル文を実在人物の名言として表示しない。ことわざの意味確認先は以下。本文の説明は独自の言い換え。
- 思い立ったが吉日：https://www.kanjipedia.jp/kotoba/0002766600
- 急がば回れ：https://www.kanjipedia.jp/kotoba/0001390300
- 急いては事を仕損じる：https://www.kanjipedia.jp/kotoba/0001393800

## 確認方法
`npm run check`：既存14件と追加17件。`tests/ui_offline_test.py`：ローカルはDOM/保存アダプタ、`LUCKY_HTTP=1`は実HTTP・ブラウザ保存・Service Workerの確認。ローカルDOM試験だけを本番やiPhone実機の検証と呼ばない。

Cloudflare本番は既存のWorkers BuildsとGit連携を使う。新しいAPIトークンや一時Workerは作成しない。`scripts/verify-live.mjs` は候補URLを調査し、6ファイルのSHA256一致を確認するだけで、デプロイ操作は行わない。
