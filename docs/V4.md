# lucky v4 — 迷ったときの、小さな味方。

## What changed

The product is no longer led by a menu of randomizers. Home offers one immediate draw with no required memo, mood, account or setup. Five games remain available behind a single method switch. Odds and the distinction between the random result and the user's own choice are unchanged.

The core loop is **a small uncertainty → a fair suggestion → noticing one's reaction → an independent choice → an optional tiny next step → a private record**. The result is never an instruction. The user may choose the opposite, pause, or finish without recording anything. The result is not automatically saved. The primary result action records intention, not verified real-world completion.

## Experience

- Warm paper, forest green and quiet brass; a cohesive four-leaf mark, coin, app icons, responsive layouts and a night theme.
- One-tap coin from the home screen. Memo and before-mood are optional. Other methods remain a preference, not another onboarding step.
- Four everyday starter examples: a different walk, a message to a friend, a page of a book, a short rest. These are fixed local examples, not AI advice.
- Four optional after-feelings, with non-diagnostic wording; three equally weighted own-choice buttons. No own-choice button is preselected visually. Saving without selecting records `undecided` explicitly in the existing schema.
- A small first-step prompt appears only after the user selects their own answer. Rest and postponement have equally legitimate prompts. Optional plans are stored as ordinary reflection text, preserving the v2 record schema.
- Three navigation destinations: きっかけ / あしあと / ことば. Mobile bottom dock and desktop top navigation.
- Calendar dates show only that date, including a real empty state; no fallback to other dates. Search covers notes, before-text and reflections. Users can edit reflections and delete one record after confirmation.
- Existing words, proverb source links, favorites, draft schema, profile-name key, theme key and old records are retained. Backups merge non-destructively. Existing v1 records are not overwritten.
- Single-flight draw and save; corrupted record data is not silently replaced; storage failure leaves the screen intact. Personal text is always inserted using textContent/value.
- No third-party scripts/fonts, analytics, accounts, note uploads, location access, payment or ads. Sharing sends the generic app URL, not the user's note.

## What this release does NOT establish

This is an implemented product hypothesis, not proof of commercial demand. No price, subscription, conversion claim, app-store listing or payment flow is introduced. The application remains a local-first web app/PWA, without multi-device synchronization.

Record exports include saved records, not draft notes, favorites or the display name. The UI states this explicitly. Browser-data deletion may remove local records. Backup/restore and raw-data rescue are exposed in Settings.

The local keyword guard is a limited aid, not an AI safety classifier. Health, safety, serious financial and legal decisions are outside the app's purpose. No probability adjustment, money rewards, streaks or guilt-based notifications were added.

## Commercial validation next

Test with people at the moment of an actual, low-stakes everyday hesitation. Observe whether they can start without guidance, whether the result reveals a preference, whether the optional next step feels useful rather than like homework, and whether they return voluntarily when another hesitation appears. Ask for concrete examples rather than whether they “like the idea.” These outcomes and willingness to pay have not yet been established.

Potential paid value is a hypothesis to test, not an implemented feature: personal themes and reusable decision/reflection packs that improve this core experience. Do not sell biased outcomes, paid rerolls, or relief from artificial limits. Avoid adding a subscription merely because the app can charge one.

## Verification

`npm run check` keeps the existing decision/game/journal checks; asset tests align package, UI and service-worker versions. `npm run build` retains the existing static build.

`tests/ui_offline_test.py` runs under a real HTTP origin with the production CSP, isolated profiles and deterministic RNG only in test initialization. It covers one-tap start, independent choices, duplicate saves, all games including ties, history dates/search/editing, backups, unsafe HTML text, storage failures, legacy records, multiple viewport widths and an actual service-worker offline reload.

On main, `scripts/verify-live.mjs` compares SHA-256 of the five deployed shell files with the checked-out source. `tests/verify_public_ui.py` then exercises the actual public URL, saves only within its disposable browser profile, and captures mobile/desktop screenshots. GitHub changes are not evidence of deployment until those checks pass. Cloudflare and exammaker deployment configuration are not changed by this release.
